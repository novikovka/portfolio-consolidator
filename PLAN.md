# Пошаговый план

План для меня: что делать руками, что просить у ИИ и как проверять результат.
Требования лежат в [REQUIREMENTS.md](REQUIREMENTS.md), правила для ИИ — в [RULES.md](RULES.md).

**Ритм каждого шага:**
1. Новый чат с ИИ → прикрепить `README.md`, `REQUIREMENTS.md`, `RULES.md` → вставить промпт шага.
2. ИИ рассказывает план **без кода** → я упрощаю или подтверждаю.
3. ИИ пишет код → я **проверяю руками** по пункту «Проверка».
4. Работает → `git commit`. Сломалось → прошу починить; если ИИ зациклился → `git restore .` и начинаю шаг заново.

**Базовый промпт (начало каждого шага):**
> Прочитай README.md, REQUIREMENTS.md и RULES.md. Мы делаем шаг **X.Y** из PLAN.md. Сначала расскажи план простыми словами и предложи варианты, начиная с самого простого. Код не пиши, пока я не подтвержу. Задавай вопросы, если чего-то не хватает.

Отмечай выполненное галочками прямо в этом файле.

## Этап 0. Подготовка (Windows 10) · ~1 вечер

### 0.1. Установить инструменты
- [ ] **Python 3.12** с python.org. В первом окне установщика поставить галочку **«Add python.exe to PATH»**.
- [ ] **Git for Windows** с git-scm.com (все настройки по умолчанию).
- [ ] **PostgreSQL** (последняя стабильная версия) с postgresql.org → Download → Windows (установщик EDB). Порт оставить 5432, **пароль пользователя `postgres` записать**. pgAdmin оставить, Stack Builder можно пропустить.
- [ ] **Редактор:** Cursor или VS Code.

**Проверка.** В PowerShell должно выполниться:
```
python --version
git --version
```
Должен открыться pgAdmin и подключиться к серверу с записанным паролем.

### 0.2. Настроить Git и GitHub
- [ ] Зарегистрироваться на github.com (если ещё нет).
- [ ] Создать репозиторий `portfolio-consolidator`. Можно публичный: личные данные туда не попадут благодаря `.gitignore`.
- [ ] В PowerShell:
```
git config --global user.name "Имя Фамилия"
git config --global user.email "почта@от.github"
```
- [ ] Клонировать репозиторий в удобную папку, положить туда `README.md`, `REQUIREMENTS.md`, `PLAN.md`, `RULES.md` и закоммитить: «Спецификация проекта».

**Проверка:** на github.com в репозитории видны 4 файла.

### 0.3. Разрешить виртуальные окружения в PowerShell
По умолчанию Windows не даёт активировать окружение Python. Один раз выполни:
```
Set-ExecutionPolicy -Scope CurrentUser RemoteSigned
```

### 0.4. Создать базу данных
- [ ] В pgAdmin создать пользователя (Login/Group Role) `portfolio_app` с паролем и правом входа (Can login).
- [ ] Создать базу `portfolio`, владелец — `portfolio_app`.

**Проверка:** в pgAdmin видна база `portfolio`.

### 1.5. Интерфейс: новая операция, журнал, позиции
Перед промптом приложи к чату скриншоты макетов «Новая операция», «Операции» и «Портфель» (правило №7).

**Промпт:** базовый + «Сделай три страницы по макетам: "Новая операция" — форма по REQUIREMENTS 3.6, пока только покупка и продажа, тикер вводится вручную; "Операции" — журнал с датой, временем и заметкой, с удалением и редактированием; "Портфель" — таблица позиций (кол-во, средняя цена, вложено). Пока один счёт по умолчанию. UI работает только через portfolio_service».

**Проверка (US-1, US-2, US-3):**
- [ ] Сумма сделки в форме пересчитывается при вводе количества, цены и комиссии.
- [ ] Время и заметка сохраняются и видны в журнале.
- [ ] «Сохранить и добавить ещё» очищает форму, но оставляет счёт и дату.
- [ ] Купить 10 SBER по 250 и 10 SBER по 300 → в позициях 20 шт., средняя 275.
- [ ] Продать 5 SBER → 15 шт., средняя 275.
- [ ] Продать 100 SBER → понятная ошибка, операция не сохранилась.
- [ ] Удалить одну покупку → позиции пересчитались.
- [ ] Закрыть приложение, перезагрузить компьютер, запустить снова → данные на месте.
- [ ] Коммит: «Этап 1: операции и позиции» + `git push`.

## Этап 5. Сервер на Raspberry Pi 5 · US-11

### Что нужно купить или проверить
- [ ] Raspberry Pi 5 (4 ГБ хватит с запасом).
- [ ] **Официальный блок питания 27 Вт** (USB-C).
- [ ] Носитель: лучше SSD (M.2 HAT или USB-SSD), минимум — microSD A2 на 32 ГБ+.
- [ ] Корпус с активным охлаждением.
- [ ] Подключение к роутеру (лучше кабелем).

### 5.1. Установить систему
- [ ] Raspberry Pi Imager → Raspberry Pi OS **Lite (64-bit)**.
- [ ] В настройках Imager: имя хоста `portfolio-pi`, пользователь и пароль, Wi-Fi (если без кабеля), **включить SSH**.
- [ ] Включить Pi, подождать 2–3 минуты.

**Проверка:** в PowerShell `ssh пользователь@portfolio-pi.local` пускает внутрь.

### 5.2. Установить PostgreSQL, Python и приложение
**Промпт:** базовый + «Мы на Raspberry Pi OS Lite 64-bit. Дай пошаговые команды: установить PostgreSQL и python3-venv через apt, создать пользователя и базу как на Windows, склонировать репозиторий, создать окружение, установить зависимости, применить schema.sql. Объясняй каждую команду».

**Проверка:**
- [ ] `streamlit run app.py` на Pi → с ноутбука открывается `http://portfolio-pi.local:8501`.
- [ ] Коммит изменений, если они были.

### 5.3. Перенести данные с ноутбука
**Промпт:** базовый + «Как перенести базу portfolio с Windows на Pi через pg_dump/pg_restore?»

**Проверка:** на Pi видны все мои операции и счета.

### 5.4. Автозапуск
**Промпт:** базовый + «Сделай systemd-сервис в `deploy/portfolio.service`, чтобы приложение запускалось при старте Pi и перезапускалось при падении».

**Проверка:**
- [ ] `sudo reboot` → через 2 минуты приложение открывается само.
- [ ] С телефона в домашнем Wi-Fi открывается `http://portfolio-pi.local:8501` (если `.local` не работает на телефоне, используем IP Pi).

### 5.5. Бэкапы
**Промпт:** базовый + «Скрипт `deploy/backup.sh`: ежедневный pg_dump в папку бэкапов, хранить 14 последних, запуск через cron или systemd timer (NF-5)».

**Проверка:**
- [ ] Запустить скрипт вручную → появился файл дампа.
- [ ] На следующий день появился ещё один дамп.
- [ ] (Желательно) раз в неделю копировать свежий дамп на ноутбук или в облако.

### 5.6. Доступ вне дома
- [ ] Зарегистрироваться на tailscale.com, установить Tailscale на Pi (по инструкции с сайта), на телефон и ноутбук, войти в один аккаунт.
- [ ] **Не** открывать порты на роутере.

**Проверка (US-11):**
- [ ] Выключить Wi-Fi на телефоне, включить Tailscale → приложение открывается через мобильный интернет.
- [ ] Коммит: «Этап 5: деплой на Raspberry Pi» + `git push`.

### Как обновлять приложение на Pi
Разрабатываю и проверяю на ноутбуке → `git push` → на Pi по SSH: `git pull` → `sudo systemctl restart portfolio`.
